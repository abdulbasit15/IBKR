Futures 2R Bot — Configuration & Overview

JSON reference for scalping_v2.json (paper) / scalping_v2_live.json (live) + how the bot trades NQ · ES · GC intraday (RTH only; YM optional, off).

Paper-first. scalping_v2.json ships paper:true (gateway 4002) and dry_run:false (it will place paper orders). LIVE needs paper:false and the CLI flag --i-understand-live (use .\scalping.ps1 -Live, which runs scalping_v2_live.json). No live account without LPL pre-clearance. Not financial advice.
Full-size contracts: NQ · ES · GC. Since 2026-10-09 the bot trades the full-size E-mini Nasdaq (NQ, $20/pt), E-mini S&P (ES, $50/pt) and Gold (GC, $100/oz) — 10× the micros — so it no longer overlaps your supertrend_bot, which trades MNQ/MES/MGC on the same paper account. Futures positions net per contract, and NQ ≠ MNQ, so the two bots stay independent. The foreign-exposure guard still blocks a symbol if anything else ever trades NQ/ES/GC on the account. 1 contract of each needs a sizeable account (typical risk per trade: NQ ~$2,900 IB Trend / ~$550 confluence; GC ~$2,300; ES ~$1,150). To go back to micros, change the symbols keys to MNQ/MES/MGC and the strategy symbol lists.

Overview — what the bot does

Timeframe & cadence

  • 5-minute bars, RTH only 09:30–16:00 ET (bars 09:30…15:55).
  • Decides once per bar, bar_delay_sec (6 s) after each 5-minute close.
  • Intraday only — flat by 16:00 (or the strategy window end).
  • Every trade: structural stop, target = 2 × risk from the actual fill (2:1).

Data & parity with the backtest

  • All bars come from IB (ContFuture 5-min TRADES, RTH): history_days at start of day, then today's bars each bar.
  • Orders go to the current front month (NQZ6, ESZ6, GCZ6 as of Oct 2026), re-resolved every morning.
  • Signals: today's completed bars are replayed through the same engine as the backtest (scalping_v2_core.py); scalping_v2_parity_test.py proves 623/623 trades identical bar-by-bar.

Strategies (the four 2:1 winners from the time-window study)

orb2nd
failed break → reverse		Opening range = 09:30–09:45. First 5-min close beyond one side, then a close back inside, then a close beyond the opposite side → market entry that way. Stop = extreme of the failed break (cap 1×OR). 2R target, else flat at 11:30. 09:30–11:30 · flatNQ GC2.65 (NQ 3.83, GC 1.94)
h2l2_trend
trend pullback		Al Brooks High-2/Low-2: EMA20 rising, price above EMA20 & VWAP, daily trend up (mirror short). After the first pullback “H1”, a lower-high bar → buy-stop 1 tick above it (valid 1 bar) = the H2. Stop = pullback low − 1 tick (skip if > 3×ATR). From 10:00, max 3/day. 2R target else 16:00.09:30–11:30 · holdNQ GC1.70 (NQ 1.80, GC 1.51)
confluence_pb
trend continuation		Five factors agree: daily trend, first-30-min return, price vs prior close, price vs VWAP, 30-min momentum. A bar dips to EMA9 and closes back beyond it → market entry. Stop = 1×ATR(14,5m). Max 4/day. 2R target else 16:00. 13:30–16:00 · holdNQ GC1.28 (NQ 1.22, GC 1.33)

ES is left out of h2l2/orb2nd/confluence and YM is off entirely because those combinations lose in the backtest (see stocks/Stocks_Report.html futures matrix). Full numbers: backtest_results.html.

Daily timeline (ET)

TimeWhat happens
09:00Day init: resolve front-month contracts, load history_days of RTH bars, re-sync own trades from IB executions, flatten any stale trade from a previous session, foreign-exposure check.
09:35:06 … 16:00:06Every 5 minutes: fetch today's bars, replay each enabled strategy (in strategy_priority order) → place a bracket when it signals at the latest bar.
09:45 →orb2nd can fire (needs the 15-min OR). h2l2_trend from 10:00.
11:00:06ib_trend decision (IB break confirmed by the 10:55 bar).
11:29:40orb2nd positions flattened (window end − flatten_lead_sec); unfilled morning entries cancelled.
13:30 → 15:25confluence_pb entries.
15:59:40All remaining positions flattened at market; children cancelled. Safety sweep again at 16:02.

Orders & exits

  • Bracket: parent (MKT, or STP for h2l2 stop-entries, TIF entry_tif) + take-profit LMT + stop-loss STP (both GTC, OCA, children of the parent). A filled position is never unprotected; if the bot dies the GTC stop stays on the server.
  • Target re-anchor: on the entry fill the take-profit is moved to exactly fill ± 2 × (fill − stop) — the backtest measures R from the fill.
  • Stop-entry expiry: an unfilled h2l2 buy/sell-stop is cancelled after 1 bar (as in the backtest).
  • Time exit: at the window end (flat mode) or 16:00 (hold): cancel children → re-sync fills → MKT for exactly this trade's remaining quantity. The bot never closes a position it didn't open.
  • Tagging: every order has orderRef = sv2|<trade-id>|entry|tp|sl|eod|window; on restart/reconnect the bot rebuilds its trades from today's executions with that tag.

How to run (build & launch)

# from Trading Strategies\scalping-v2
python scalping_v2_bot.py --check                # config + imports + engine self-test (no network)
python scalping_v2_bot.py --status               # READ-ONLY: contracts, history, today's levels + what each strategy did
python scalping_v2_bot.py --test-orders NQ      # PAPER ONLY: place a far-away bracket, verify, cancel
python scalping_v2_bot.py                        # run the scheduled loop (leave running all session)

# packaged like the other bots
.\scalping.ps1                    # PAPER: builds the exe if missing, then runs it supervised (auto-restart; STOP.txt to stop)
.\scalping.ps1 -Build             # rebuild the exe (after a code change), then run on paper
.\scalping.ps1 -Build -NoRun      # rebuild only
.\scalping.ps1 -Live              # LIVE: scalping_v2_live.json + --i-understand-live (asks you to type LIVE)
.\scalping.ps1 -ResetConfig       # overwrite dist\*.json with the source configs (else your dist edits are kept)

python scalping_v2_backtest.py --html            # backtest the config + rebuild backtest_results.html
python scalping_v2_parity_test.py                # live-decision vs backtest parity (run after any scalping_v2_core change)
python scalping_v2_sim_test.py --days 60         # full bot code vs fake broker on historical bars

Start it any time — before 09:00 it waits; mid-session it initialises immediately and only acts on new bars (it never back-fills a missed signal).

Strategy blocks (strategies.<key>)

KeyMeaning
enabledTurn the strategy on/off.
symbolsWhich contracts it trades (subset of the symbols block).
window["HH:MM","HH:MM"] ET — entries only inside; event setups that fire before the window are skipped for the day.
modehold (2R / stop / 16:00, entries ≤ 15:25) or flat (also out at the window end).
paramsStrategy parameters — see below.

ib_trend params

  • trend: e10/e20/e50 daily EMA trend filter · none · long (default e20)
  • entry: confirm (11:00 only) · first (first close beyond IB)
  • stop: mid (IB midpoint) · cap (tighter of mid / 0.5×IB)
  • nw: skip IB wider than nw × 14-day avg range (9.9 = off)

orb2nd params

  • orm: opening-range minutes (15)
  • dtf: require daily trend (false)

h2l2_trend params

  • maxr: max risk in ATRs (3.0)
  • dtf: require daily trend (true)
  • max_trades: per day (3)

confluence_pb params

  • trig: pb (EMA9 pullback) · align
  • k: stop = k × ATR (1.0)
  • mx: max trades/day (4)

Change a parameter → run python scalping_v2_backtest.py to see its effect before running the bot with it.

Examples

NQ only, all four strategies

"symbols": {"NQ": {"enabled": true, ...}, "ES": {"enabled": false, ...}, "GC": {"enabled": false, ...}}

Back to micros (e.g. a smaller live account)

"symbols": {"MNQ": {...}, "MES": {...}, "MGC": {...}}   # and use MNQ/MES/MGC in each strategies.<key>.symbols list

Only the 11:00 IB Trend trade on all three (fewest trades, simplest)

"orb2nd": {"enabled": false, ...}, "h2l2_trend": {"enabled": false, ...}, "confluence_pb": {"enabled": false, ...}

Risk-based sizing ($250 per trade, max 3 contracts)

"sizing": {"mode": "risk", "risk_usd": 2500, "max_contracts": 3}

Going live

  1. Paper for several weeks; compare scalping_v2_trades_*.csv with python scalping_v2_backtest.py for the same dates.
  2. Edit dist\scalping_v2_live.json: set account (U…), check max_risk_usd, daily_loss_limit_usd, contracts = 1.
  3. Live Gateway on 4001, API not read-only; no other bot on NQ/ES/GC on that account.
  4. .\scalping.ps1 -Live (type LIVE to confirm). Scale contracts only after live results match paper.
