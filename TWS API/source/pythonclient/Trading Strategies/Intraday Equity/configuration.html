Intraday Equity — Configuration

JSON config reference for equity.json (long-only intraday equity bots, ib_async).

The daemon is fully config-driven: runner.py (or the frozen dist\intraday_equity.exe) reads equity.json next to it and launches one thread per active strategy, each on its own IB client id. Change strategies, windows, sizing, or risk with no code changes. Defaults: paper account DU672616, IB Gateway port 4002.

Connection / top-level

KeyMeaning
host / portTWS/Gateway. Default 127.0.0.1 / 4002 (paper gateway; 4001 = live).
accounts / default_accountAccount list + the one to trade (e.g. "DU672616").
client_id_baseBase API client id (default 30). Each active strategy gets base + index; the start-of-day bootstrap connection uses base + 90.
market_data_type1 live · 2 frozen · 3 delayed · 4 delayed-frozen. Paper DU672616 has no live sub → 3 makes bars/quotes/VWAP work; 1 yields NaNs that silently block entries when require_vwap is on.
hist_min_interval_secMin seconds between historical-data requests (shared rate limiter). Default 2.0.
reconnect_backoff_secresilience Steady reconnect retry interval (default 60). Both the bootstrap connect and every strategy retry fast (5s × 3) then settle to this. Retries continue until connected or the EOD flatten time, so a Gateway that isn't up yet is waited out rather than aborting the day.
preopen_lead_minWake this many minutes before the first trade window (default 10). The daemon stays dormant — with no broker connection — outside the session.
dormant_poll_secHow often to re-check while dormant (default 60).

Active strategies

KeyMeaning
active_strategiesList of strategy display-names to run. Each must have a matching block under strategies. The display-name (spaces/dots allowed) is sanitised to drive log/report/CSV filenames, e.g. "ORB SIP - 9.35" → ORB_SIP___9_35.
_available_strategies_off / _noteDocumentation-only: names built + configured but disabled (net-negative in backtest). Move a name into active_strategies to enable it.

Registered strategy_type → class (in runner.py): orb_stocks_in_play, nr7_compression, pdh_breakout, vwap_pullback, trend_pullback, range_breakout_retest, sr_bounce.

Shared risk (shared_risk)

Applied to all strategies; a per-strategy block may override several of these keys.

KeyMeaning
risk_per_trade_pctFraction of the strategy's capital risked at the stop (default 0.01 = 1%). Ignored when fixed_stocks > 0.
max_concurrent_positionsCap on simultaneous open names across the book.
max_positions_per_sectorCap per sector (uses sector_map).
aggregate_open_risk_pctCap on total open risk-at-stop as a fraction of capital.
daily_loss_limit_pctHalt new entries once the day's realized loss hits this fraction.
min_stop_pctFloor on stop distance (protects sizing from a too-tight structural stop).
min_rrMinimum reward:risk for an entry to be taken.
eod_flatten_timeET time to flatten everything and stop for the day (e.g. "15:55"). Checked on every tick.
market_data_line_capCeiling on simultaneous market-data subscriptions.
regimeMarket gate: spy_downtrend_gate, spy_max_intraday_drop_pct, vix_max — blocks new entries in a weak tape.

Scanner / universe

Each strategy's build_watchlist() seeds from the IBKR native scanner (when configured) then applies its own gap/RVOL/ADV filters. Use the built-in ScannerSubscription fields (abovePrice/belowPrice/aboveVolume) — they work without a market-data entitlement; generic TagValue filters require entitlement (error 162), so the scanner.tag_filters block is left empty. fallback_to_universe: true uses universe_symbols if a scan errors or returns nothing.

Build & run

CommandWhat
python runner.pyRun from source (preferred while iterating). Daemon: dormant off-session, trades on trading days.
.\Intraday.ps1Build one-file dist\intraday_equity.exe via PyInstaller (auto PyPI → Aliyun mirror fallback) and stage equity.json.
.\run_intraday.ps1Supervisor: launches the exe and relaunches on any exit (outer safety net on top of the bot's own reconnect). Stop with a STOP.txt file.
Resilience. The bot keeps retrying the IB connection (fast, then every reconnect_backoff_sec) on startup and after a drop, until connected or the EOD flatten time — so a Gateway that isn't up yet, or its daily restart, is ridden out. The run_intraday.ps1 supervisor is the outer net if the process itself ever exits.
Paper vs live gateways don't mix. One login per gateway; paper (DU…) and live (U…) can't share a port. Paper-first, always.
