Supertrend v1 — Strategy Logic

How the bot turns bars into orders. Distinguishing feature: partial take-profit.

Cadence & indicators

Evaluate once per completed bar (on the last closed bar, bars[-2]); heartbeat between bars for connection + stop-fill checks. At most one entry per bar per symbol. hist_duration auto-covers the largest indicator warmup then clamps to a safe max for the bar size.

Regime classification (hysteresis)

Each bar the tape is labelled TREND or CHOP using Choppiness + ADX, and the state is held per symbol so it doesn't flip-flop at the boundary:

When regime_filter is on it supersedes the always-on RSI/MACD gates (applies momentum by regime instead). It does not override DEMA. Any filter that can't be evaluated (too little history) blocks the entry.

Partial take-profit — v1's feature

Scale-out on trend trades v1

R = |entry − initial stop|. Trim a fraction at each R-multiple via resting LIMIT orders (visible in TWS), then trail the runner.

  • Default ladder: trim 50% at 2R.
  • After a trim at ≥ tighten_after_r, the runner switches to a trail_r-R trailing stop (locks profit).
  • The protective stop is resized to the reduced qty; TPs are cancelled on any stop/flip/EOD exit and re-armed on reconnect (so a half-qty TP can't orphan into a new position).
  • Needs fixed_stocks ≥ 2. Backtests positive in both regimes — see performance.

Position management (each bar)

  1. Partial-TP first — fire any reached tranche, shrink the position, tighten the runner.
  2. Signal unchanged → trail the single stop toward the Supertrend line (favourable direction only).
  3. Signal flipped → cancel the stop and flatten. In long_short, immediately open the opposite side; else go to cash.
Invariant: never an unprotected position, never stacked stops. Entry attaches a stop atomically (parent transmit=false → stop child transmit=true); every top-up/adoption cancels all stops and places ONE consolidated stop for the full held qty.

Sizing, sessions & reconnect

AreaBehaviour
Sizingfixed_stocks > 0 → target position, tops up to it (never stacks duplicates on restart). = 0 → floor(capital × risk_pct / (entry − stop)), stop floored at min_stop_pct, capped by max_position_notional. Futures size by multiplier (MNQ $2/pt, MES $5/pt).
RTHmarket entries, native STP stop.
ETH / 24Horders flagged outsideRth; entries use a marketable-limit chase (market orders reject outside RTH); stops STP (futures) or STP-LMT (outside-RTH equities).
24H equities overnightroutes to the OVERNIGHT venue (LIMIT-only, no GTC) → synthetic stop (monitor + marketable-limit exit on breach). Futures never use OVERNIGHT.
Startup / reconnectsync_existing(): read a LIVE position snapshot, adopt per symbol, flatten if the Supertrend already flipped, else top up + consolidate to one stop (and re-arm the TP). Swing stops are GTC + server-side, so positions stay protected while the process is down.
Reliability: v1 wraps loop/reconnect waits in _safe_sleep(), which swallows the CancelledError/ConnectionError raised when IB Gateway's daily restart peer-closes the socket — so the strategy thread survives and reconnects on the next tick. (This is one of the two things the v2 branch lacks.)
