Supertrend v1 — Configuration

JSON config reference for supertrend.json (the partial-take-profit line).

The bot is fully config-driven: it reads the JSON next to it (or a path you pass) and needs no code changes to switch symbol, timeframe, ST params, direction, session, filters, or sizing. The distinguishing v1 block is partial_tp; for the mean-reversion branch see v2's configuration.

Connection / top-level

KeyMeaning
host / portTWS/Gateway. Default 127.0.0.1 / 4002 (paper gateway; 4001 = live).
client_id / client_id_baseBase API client id (default 40). Each strategy gets base + index (or its own client_id). Keep clear of the equity bots (30/31/32).
accounts / default_accountAccounts the config intends to trade. Effective account is resolved against the login's managed accounts at connect (adopts the sole managed account if the configured one isn't managed).
market_data_type1 live · 2 frozen · 3 delayed · 4 delayed-frozen. Paper DU672616 has no live sub → use 3.
directionlong_only (default) / short_only / long_short.
intraday_modefalse = swing (hold overnight, GTC stop). true = intraday (flatten at eod_flatten_time, DAY stop).
eod_flatten_timeET flatten time when intraday (e.g. "15:55").
entry_window[start, end] ET — new entries only inside this window (exits/stops always active). Defaults to the session for the chosen market_hours.
entry_on_flip_onlyfalse = enter whenever the regime matches. true = require a fresh Supertrend flip.
poll_interval_secHeartbeat seconds (default 30) for connection/stop checks between bars. Signal is still evaluated once per bar.
reconnect_backoff_secSteady reconnect retry interval (default 60).
hist_timeout_secPer historical-request timeout (default 20).
data_fail_reconnect_cyclesConsecutive no-data bar-evals before forcing a session reset (default 4) — recovers from a stolen data line.
max_concurrent_positionsCap on simultaneous open names (per strategy).
log_dir / trade_log_csvLog folder and CSV base name (per-strategy _<name> suffix is added automatically).

Per-strategy

Inside a strategies array (one thread per entry), or at the top level for single-strategy mode. Common top-level keys are inherited and can be overridden per strategy.

KeyMeaning
nameLabel for logs / CSV / client-id display.
accountAccount to trade (resolved to the managed account).
symbolse.g. ["SOXL"], ["GOOG","AMZN"], or a future root ["MNQ"].
sec_typeSTK (default, equities on SMART) or FUT (CME futures; front-month auto-selected, sized by multiplier). With FUT also set exchange (e.g. CME) and currency.
bar_sizeAny IB bar: "1 min", "5 mins", "15 mins", "1 hour", "1 day". Sets both the signal timeframe and the evaluation cadence. Deploy on 15 mins (best backtest timeframe).
market_hoursRTH (09:30–16:00) / ETH (04:00–20:00) / 24H (all hours, incl. OVERNIGHT venue for equities). ETH/24H flag outsideRth.
supertrend.atr_period / .multiplierST config, e.g. 10 / 3.0.
hist_durationHistory per evaluation. Auto-derived + clamped to a safe max for the bar size if omitted (only needs to exceed the DEMA/ATR warmup).
sizing.fixed_stocksTarget total shares/contracts (bot tops up to it; authoritative over the notional cap). 0 → % risk. ≥ 2 required for partial-TP.
sizing.risk_per_trade_pct / .strategy_capital% risk-at-stop sizing when fixed_stocks = 0.
sizing.min_stop_pctFloor on stop distance so a too-tight Supertrend line can't blow up size.
sizing.max_position_notionalNotional cap (applies to % risk; only warns for fixed_stocks).

Filter blocks (all optional)

BlockMeaning
dema_filter{enabled, period=200} — core entry gate (default ON): long only if close > DEMA, short only if close < DEMA.
adx_filter{enabled, period=14, threshold=20} — trend-strength gate: enter only when ADX ≥ threshold. Shorthand "adx": 20.
rsi_filter{enabled, period=14, long_min=50, short_max=50} — momentum must agree: LONG needs RSI > long_min, SHORT needs RSI < short_max. Shorthand "rsi": 50.
macd_filter{enabled, fast=12, slow=26, signal=9} — LONG needs histogram > 0, SHORT needs < 0.
regime_filter{enabled, adx_period=14, chop_period=14, adx_trend=25, chop_trend=38, chop_range=61, chop_action, trend_momentum=false}. Classifies TREND vs CHOP (Choppiness + ADX, hysteresis). When enabled it supersedes the always-on RSI/MACD gates (not DEMA). chop_action = stand_aside (default) / momentum.
Filters block when they can't be evaluated. If there's too little history to compute a filter, the entry is refused (by design). Widen hist_duration if you see "insufficient bars".

Partial take-profit v1 feature

Scale-out on trend trades. R = |entry − initial stop|. Trims a fraction at each R-multiple via resting LIMIT orders (visible in TWS), then trails the runner. Needs fixed_stocks ≥ 2.

KeyMeaning
partial_tp.enabledTurn scale-out on.
partial_tp.tranchesLadder, e.g. [{"fraction":0.5,"r_multiple":2}] (trim 50% at 2R). Backtest: 50%@2R (or 33/33@2R,3R) is the edge; finer 1R ladders don't help.
partial_tp.tighten_after_rAfter a trim at ≥ this R, switch the runner to a trailing stop that locks profit (default 2.0).
partial_tp.trail_rRunner trailing distance in R once tightened (default 1.0).

Futures, deployed — 15m regime + partial-TP

{
  "name": "DU672616_MNQ_15m", "account": "DU672616", "direction": "long_short",
  "sec_type": "FUT", "exchange": "CME", "currency": "USD",
  "symbols": ["MNQ"], "bar_size": "15 mins", "market_hours": "24H", "hist_duration": "30 D",
  "supertrend": { "atr_period": 10, "multiplier": 3 },
  "dema_filter": { "enabled": true, "period": 200 },
  "regime_filter": { "enabled": true, "chop_action": "stand_aside" },
  "partial_tp": { "enabled": true, "trail_r": 1.0, "tighten_after_r": 2.0,
                  "tranches": [ { "fraction": 0.5, "r_multiple": 2 } ] },
  "sizing": { "fixed_stocks": 4, "max_position_notional": 500000 }   // ≥2 so half actually trims
}

Paper vs live gateways don't mix. One login per gateway; paper (DU…) and live (U…) can't share a port. Multiple live accounts at once require an FA/advisor-master login. Paper-first, always — no live account without LPL pre-clearance.
